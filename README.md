# IDS-AI

Hybrid AI-powered Intrusion Detection System — combines a Machine Learning model and a local LLM served by Ollama to classify network traffic in real time.

## Architecture

```text
IDS-AI/
├── backend/
│   ├── data.csv              # Network dataset (211,043 entries, 44 columns)
│   ├── data.ipynb            # Exploratory data analysis notebook
│   ├── train.py              # Training + data augmentation + best-model selection
│   ├── detector.py           # ML inference pipeline
│   ├── model.py              # LLM integration (Ollama by default, HuggingFace optional)
│   ├── main.py               # FastAPI app (POST /analyze, GET /health)
│   ├── knowledge_base.txt    # Cyber attack reference used in the LLM prompt
│   ├── best_model.joblib     # Saved model bundle (generated by train.py)
│   └── requirements.txt
├── frontend/                 # React UI (Dashboard + alerts)
├── database/                 # MongoDB configuration
│   ├── alerts.py             # Alert repository (create/list/status update)
│   ├── config.py             # Async Motor client + connection helpers
│   ├── models.py             # Pydantic models: Alert, NetworkTraffic
│   └── traffic.py            # Network traffic repository
├── pyproject.toml
└── uv.lock
```

## Detection Pipeline

```text
Network request
      │
      ▼
 [Preprocessing]
 Categorical encoding + normalization
      │
      ▼
 [ML Model]  ─────── normal ───────────▶  { label: normal, confidence }
 RF / XGBoost / IsoForest
      │
   anomaly
      │
      ▼
 [LLM — Ollama]
 Knowledge base + JSON classification + recommended action
      │
      ▼
 { Normal | Suspicious | Malicious, confidence, explanation, action, severity }
```

## Trained ML Models

| Model                  | Type                              |
| ---------------------- | --------------------------------- |
| RandomForestClassifier | Supervised                        |
| XGBClassifier          | Supervised                        |
| IsolationForest        | Unsupervised (anomaly detection)  |

The best model is **automatically** selected by F1-score and saved to `best_model.joblib`.

## Data Augmentation

Before training, **SMOTE** (Synthetic Minority Over-sampling Technique) is applied on the training split to balance all attack-type classes to the same sample count. This prevents the model from being biased toward the majority class.

- Applied **only on the training set** to avoid data leakage.
- Falls back gracefully if `imbalanced-learn` is not installed.
- Install the dependency: `pip install imbalanced-learn`

## Quick Start

### 1. Backend

```bash
cd backend
python -m venv venv && source venv/bin/activate
pip install -r requirements.txt
```

### 2. Ollama LLM

Install and start Ollama, then pull the default model:

```bash
ollama pull mistral
ollama serve
```

`ollama serve` keeps running in the terminal. Open another terminal for the API.

To use another Ollama model, for example `llama3.1`, set:

```bash
export LLM_PROVIDER=ollama
export LLM_MODEL_NAME=llama3.1
```

### 3. Training

```bash
pip install imbalanced-learn   # required for SMOTE data augmentation
python train.py
```

Prints a comparison table for all 3 models and saves the best one:

```text
------------------------------------------------------------------------------
Model                   Accuracy  Precision   Recall       F1
------------------------------------------------------------------------------
RandomForest              0.9912     0.9934   0.9928   0.9931
XGBoost                   0.9905     0.9921   0.9919   0.9920
IsolationForest           0.7841     0.8102   0.7630   0.7859
------------------------------------------------------------------------------
```

### 4. Start the API

```bash
uvicorn main:app --reload
```

API available at `http://localhost:8000` · Interactive docs: `http://localhost:8000/docs`

## Database

MongoDB is used to persist alerts and network traffic records. The `database/` module uses **Motor** (async driver).

**Collections:**

| Collection        | Model            | Description                              |
| ----------------- | ---------------- | ---------------------------------------- |
| `alerts`          | `Alert`          | Intrusion detection alerts with severity |
| `network_traffic` | `NetworkTraffic` | Raw traffic records used for ML logging  |

**Alert fields:** `timestamp`, `type`, `message`, `source_ip`, `severity` (`low` / `medium` / `high` / `critical`)

## LLM Knowledge Base

`knowledge_base.txt` contains reference descriptions for common attack types and their network indicators. At inference time, the backend now selects the most relevant knowledge-base sections using the ML prediction, risk signals, and raw log, then injects only those excerpts into the LLM prompt. The API also returns `knowledge_matches`, `evidence`, `risk_signals`, and `top_features` so analysts can see why the system reached its decision.

## Environment Variables

| Variable          | Default                               | Description                          |
| ----------------- | ------------------------------------- | ------------------------------------ |
| `IDS_MODEL_PATH`  | `backend/best_model.joblib`           | Path to the model bundle             |
| `LLM_PROVIDER`    | `ollama`                              | `ollama` or `huggingface`            |
| `LLM_MODEL_NAME`  | `mistral`                             | Ollama/HuggingFace model to use      |
| `OLLAMA_BASE_URL` | `http://localhost:11434`              | Ollama server URL                    |
| `LLM_DEVICE`      | `auto`                                | HuggingFace only: `cpu`, `cuda`, or `auto` |
| `LLM_ENABLED`     | `true`                                | Disable the LLM by setting `false`   |
| `LLM_PRELOAD`     | `false`                               | Load the LLM at startup              |
| `CORS_ORIGINS`    | `http://localhost:3000`               | Allowed CORS origins                 |
| `MONGO_URI`       | `mongodb://localhost:27017/ids_ai`    | MongoDB connection URI               |
| `DATABASE_NAME`   | `ids_ai`                              | MongoDB database name                |
| `MONGO_ENABLED`   | `true`                                | Disable alert persistence with `false` |

With Ollama, pull the model once and keep the local server running:

```bash
ollama pull mistral
ollama serve
```

To use the previous HuggingFace path, install `transformers`, `torch`, `accelerate`, and `sentencepiece`, then set `LLM_PROVIDER=huggingface` and `LLM_MODEL_NAME=mistralai/Mistral-7B-Instruct-v0.2`.

## Dataset

`data.csv` contains 211,043 network traffic entries:

| Class       | Samples   |
| ----------- | --------- |
| normal      | 50,000    |
| backdoor    | 20,000    |
| ddos        | 20,000    |
| dos         | 20,000    |
| injection   | 20,000    |
| …           | …         |

**Target column**: `label` (0 = normal, 1 = attack)

After SMOTE, all classes in the training split are equalized to the count of the majority class.
